# Control Panel

A **Control Panel** (CP) is the bus master: it polls one or more Peripheral
Devices, sends them commands, and receives their events. In Python that role is
the [`ControlPanel`](#controlpanel) class. Each managed PD is described by a
[`PDInfo`](/python/api#pdinfo) and addressed by its bus address throughout the
API.

## Lifecycle

A CP moves through the same phases every time:

1. **Construct** — `ControlPanel(pd_info_list, ...)`, optionally passing an event
   handler and a command-completion handler up front.
2. **Register handlers** (optional) — or set them later with
   `set_event_handler` / `set_command_completion_handler`.
3. **Start** — `start()` spawns a background thread that services the bus. This
   is what satisfies OSDP's requirement to refresh the library at least every
   50ms; your application never has to poll on a timer.
4. **Wait for the link** — `online_wait_all()` / `sc_wait_all()` block until the
   PDs are online and (if keyed) the secure channel is established.
5. **Run** — submit commands with `submit_command()` and drain events with
   `get_event()` (or a registered handler).
6. **Tear down** — `teardown()` stops the thread and releases the context.

```python
cp = ControlPanel(pd_info, log_level=LogLevel.Debug)
cp.start()
cp.sc_wait_all()
...
cp.teardown()
```

::: warning Callbacks run on the library thread
Event and command-completion handlers are invoked from the background refresh
thread, not the thread that called `start()`. Guard any state they share with
your application, and keep them short — blocking in a handler stalls the bus.
The queue-based `get_event()` is the alternative when you would rather pull
events on your own thread.
:::

## Events

Events are generated by a PD and delivered to the CP. You can consume them two
ways, and may mix them:

- **Pull** — call `get_event(address)` in your own loop; it returns the next
  queued [event](/python/events) or `None`.
- **Push** — register an event handler (constructor argument or
  `set_event_handler`) that the library calls as events arrive.

```python
def on_event(address: int, event) -> int:
    match event:
        case events.CardRead(data=data):
            print(f"PD {address}: card {data.hex()}")
    return 0

cp = ControlPanel(pd_info, event_handler=on_event)
```

The event payload types are documented on the [Events](/python/events) page.

## Command completion

Every command you submit settles exactly once. A command-completion handler is
told the outcome — acknowledged, failed, flushed before it reached the wire, or
aborted at teardown — as a [`CompletionStatus`](/python/api#enumerations). The
library hands your handler its own re-marshalled copy of the original command,
so you can tell which one completed.

```python
from osdp import CompletionStatus

def on_command_complete(address, command, status):
    if status == CompletionStatus.Ok:
        print(f"{type(command).__name__} completed on PD {address}")

cp.set_command_completion_handler(on_command_complete)
```

## Commands

Build a command dataclass and submit it to a PD by address. See
[Commands](/python/commands) for every command type and its fields.

```python
cp.submit_command(101, commands.Buzzer(reader=0, control_code=BuzzerControlCode.DefaultTone))
```

`flush_commands(address)` drops any commands still queued for a PD; each dropped
command settles with `CompletionStatus.Flushed`.

## Capabilities, IDs, and flags

`get_pd_id(address)` returns the PD's [`PdId`](/python/api#pdid), and
`check_capability(address, capability)` reports whether a PD advertises a given
[`Capability`](/python/api#the-capabilities-model) and at what compliance level.
`set_flag` / `clear_flag` toggle per-PD [`LibFlag`](/python/api#enumerations)
options at runtime.

## File transfer

To send a file to a PD, register a [`FileOps`](/python/api#file-transfer)
implementation with `register_file_ops(address, fops)`, then submit a
`commands.FileTransfer`. Progress is readable via `get_file_tx_status(address)`.

## Smart cards (TRS)

To talk to a smart card on the reader, open a session and exchange APDUs in
it:

```python
with cp.trs_session(101) as card:
    answer = card.transceive(bytes.fromhex("00A4040007D276000085010100"))
```

Each call returns the card's answer once the library has settled the command,
and raises `TrsSessionError` when the exchange did not happen.
`trs_scan_enable(address)` has the library watch for cards between sessions,
which then arrive as `events.TrsCardInfo`, and `trs_get_max_apdu_len(address)`
says how large an APDU the link can carry. The session is built on
`commands.TrsStart`, `TrsSendApdu` and `TrsStop`, which can also be submitted
directly. See
[Transparent Reader Support](/libosdp/smartcard#transparent-reader-support-trs)
for the whole flow.
